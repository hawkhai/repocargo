# RepoCargo 资源交换协议

本文是随成品发布的使用级协议，不依赖开发工作区、测试源码或内部报告。命令入口以 [使用参考](usage.md) 为准；下文描述磁盘和服务端产物，不提供历史斜杠参数作为公开调用方式。

## 文件与目录

| 产物 | 内容 |
| --- | --- |
| `repocargo.yaml` | 项目配置和自动上传快照 |
| `<mainfile 文件名>.md5.txt` | 发布目录 ID；默认 `repocargo.yaml.md5.txt` |
| `datamap.txt` | 资源路径、MD5、大小和可选远端路径 |
| `version.txt` | 版本摘要，不是发布目录 ID |
| `version/<摘要>.txt` | 对应版本的索引快照 |
| `<主文件去扩展名>_dense.zip` | 小文件合包，默认 `repocargo_dense.zip` |
| ZIP 内 `metainfo.json` | 资源成员与内容 MD5 映射，保留 JSON |
| `tempdir/`、摘要侧车、缓存 | 内部数据，不是人工维护的项目配置 |

发布目录 ID 选择远端目录，可以是固定发布名或自动来源，不一定是内容 MD5。上传选择与内容版本摘要是两个概念；下载读取发布方提供的 ID 文件，缺失/空 ID 不应猜测。

## 地址与隔离

普通 FTP 资源位于 `/repocargo/<gitremote>/<ID>/<资源相对路径>`，符号位于独立 `/repocargo-symbols` 根。旧工具使用 `/gitremote` 和 `/macos_symbols`；不自动回退或迁移旧远端。

资源映射不得向上越出所选 ID，检测到时以 `UNSAFE_RELEASE_PATH` 失败。该检查不等于所有配置路径、名称转换和本地路径都具备完整沙箱防护。默认 `mainroot: .` 是推荐布局。

## datamap 三种行格式

```text
"assets/a file.bin" 0123456789abcdef0123456789abcdef 123
"assets/a file.bin" 0123456789abcdef0123456789abcdef 123 "remote/a.bin"
assets/a file.bin 0123456789abcdef0123456789abcdef 123
```

前两种为引号格式；第三种为历史无引号格式。MD5 为 32 位小写十六进制，大小为非负十进制。解析将路径分隔符统一为 `/`。

引号格式没有第四列时远端路径默认等于本地路径；旧的无引号格式推导为 `<路径>/<MD5>.<文件名>`。不能将两种三列格式简单互换。非法行不能作为有效索引使用；不要手改摘要或长度来跳过校验。

发布配置中的资源扫描与 Fetch 消费索引是两种行为。Fetch 尊重索引第四列；Python/Lite 的普通上传映射不因这列就自动重定向。

## 版本与快照

版本摘要基于“资源路径→文件 MD5”的有序 JSON 序列化：键排序、缩进 2、ASCII 转义，路径/值中的反斜杠规范为 `/`，CRLF 规范为 LF，再计算 MD5。配置自身可能参与摘要，因此配置变化也会改变版本。

basename 为 `version.txt` 且长度为 0 或 32 字节的输入，其摘要值会置空以减少循环依赖；其他长度不作该处理。`version.txt` 保存 32 字符摘要，不附加换行。

同时开启 `generate_listfile` 与 `generate_versionfile` 才将 datamap 复制为 `version/<摘要>.txt`。Fetch URL 的根目录需提供 `version.txt`，并可按该值取得快照及其资源。ID 与版本摘要不可混用。

## ZIP 与去重

小文件须严格小于 `densefile_ctrl` 才入包，默认阈值 524288 字节；Python 与 Lite 对 0 阈值的历史解释不同。主文件不会仅因是主文件自动入包；开启 ZIP 后的索引也包含 ZIP。

```json
{
  "filelist": [["./assets/a.bin", "assets/a.bin"]],
  "md5mapdict": {"0123456789abcdef0123456789abcdef": "assets/a.bin"}
}
```

`filelist` 第一项为发布机源路径，第二项为成员名；发布前应检查这类元信息是否泄露本机路径。相同内容的多个成员可能对应同一个恢复来源。空集合也可生成只有元信息的 ZIP。

ZIP 时间和部分平台元信息经过规范化，但不同机器、路径或运行库不保证 ZIP 字节完全一致。缓存会按清单和元信息摘要复用，不能仅凭文件名判断缓存有效。

## 上传顺序及失败状态

完整版/Lite 会扫描、更新配置快照，按开关生成 ZIP、索引、版本快照和目录 ID，再进行传输。复制、环境修复、Git 暂存、历史清理等副作用视配置和后端而异。

FTP 更新沿用失效协议：先将当前远端 MD5 侧车写为 `null`，再写资源，最后写真实 MD5。初始失效失败不写该资源；最终摘要失败返回错误并留下 `null`。读端不能借旧布局摘要把 `null` 当成有效缓存。侧车当前布局为 `/_md5dir/<完整远端资源路径>.md5`，历史兼容布局为资源父目录下 `_md5dir/<文件名>.md5`。

这不是多文件事务；同一个 ID 的复用、并发上传和网络中断都不保证整批一致。`--index-only` 仍有配置/生成/Git 等副作用，并可能触及特定远端流程，不能用作只读预演。

## 下载与清理

Python/Lite 需要本地配置及目录 ID。若映射含主配置，会先下载并重读配置，再决定资源、版本/索引、ZIP 和剩余传输；`upload.others` 存在时优先采用，即使它是空集合。

下载错误返回非零并停止后续步骤，但 Python/Lite 的部分路径会先删除或清空旧目标；失败不保证保留旧文件或回滚。空快照仍被接受，不保证自动退回 ZIP 恢复。不要从“资源文件存在”推断下载成功。

`clean` 删除 datamap 与上传快照所列资源的并集；会保留部分核心控制文件，但自定义主文件和被列入索引的其他配置不一定受保护。`--clear-local` 与按索引清理的方向不同。新旧工具不共享工作目录或清理范围。

## Fetch 部署

Fetch 消费发布版本与索引，验证资源大小/MD5、ZIP 成员或重复内容，再进行替换。只有本次索引包含根 `repocargo.yaml` 且其 `mainfile: repocargo.yaml` 时才运行该配置的部署阶段；本机残留配置不触发部署。

已有动作包括 `file.copy`、`config.set`、`shell.run`、`env.path.add`。下载和部署完成后才提交版本标记；单文件失败的保护不等同于整批回滚，先前成功的文件和动作可能保留。部署中断后应检查状态，不盲目重放 shell 动作。

平台及后端未实现的能力不会因格式兼容而自动补齐；详见 [已知限制](limitations.md)。
