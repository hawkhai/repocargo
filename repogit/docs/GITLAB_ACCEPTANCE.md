## 环境与方法

连接真实 GitLab 服务的专用私有测试项目，初始远程为空，同步分支为 `sync`。管理员在 GitLab 页面添加或撤销项目 Deploy Key，客户端使用 RepoGit 和实际 Git/OpenSSH 进行访问；这里的权限拒绝来自真实服务器。

**B 是本机隔离模拟，不是另一台物理电脑。** A、B 使用独立的设备密钥、SSH 配置和工作目录，两套身份的 SSH agent 与连接复用均禁用。B 没有使用 A 的私钥，测试没有向客户分发个人 SSH 私钥。

本摘要仅发布脱敏后的结果，不包含公司域名/IP、真实仓库地址、原始本机路径、设备公钥/指纹或内部日志。机器可读结果见 [GITLAB_ACCEPTANCE.json](GITLAB_ACCEPTANCE.json)。

## 已通过的场景

| 场景 | 实测结果 |
| --- | --- |
| A 未获授权时读取 | `Permission denied (publickey)`，退出码 128 |
| A 获得读写 Deploy Key 授权 | 读取成功，首次推送在空远程创建 `sync`；远程提交与本地 HEAD 一致 |
| 原有本地项目 | 初始提交历史及原有 `origin` 保持不变 |
| 独立 B 未获授权时克隆 | SSH 公钥认证拒绝，退出码 128 |
| B 获得只读授权后克隆 | 成功取回 A 的初始提交 |
| A 发布后续提交，B 拉取 | B 成功快进到 A 的新提交；提交及对应 Git 文件对象一致 |
| B 只读时提交并尝试推送 | GitLab 返回 `This deploy key does not have write access to this project.`，退出码 128；远程引用不变，B 本地提交和文件保留，读取仍成功 |
| 管理员撤销 B 授权后读取 | 新进程发起连接，SSH 公钥认证拒绝，退出码 128 |
| B 撤权后全新克隆 | SSH 公钥认证拒绝，退出码 128 |
| B 撤权后拉取 | SSH 公钥认证拒绝，退出码 1；不是本地工作区或历史分叉导致的拒绝 |
| B 撤权后推送 | SSH 公钥认证拒绝，退出码 128 |
| A 作为对照继续读写 | B 撤权前后 A 的读取正常；撤权后 A 仍能发布新提交，排除了服务整体不可用的情况 |
| 撤权后的数据边界 | B 已下载文件的哈希、本地提交和引用保持不变，未取得 A 在撤权后发布的新内容 |

Git 会转换部分子进程退出码，因此这里的退出码是各 RepoGit 命令的实际结果，不要求所有拒绝都返回同一个数字。判断撤权生效同时依据服务器认证错误及 A 的正常对照访问。

## 结论与边界

本轮验证了项目级 Deploy Key 的授权、只读读写区分和撤权效果，以及 RepoGit 的首次上传、克隆和快进拉取流程。撤权阻止后续远程访问，不会收回已经下载的源码或删除本地提交。

尚未覆盖两台物理电脑、不同网络、严格分支/标签保护、另一未授权私有仓库，以及 Git LFS/子模块。未对本轮未执行的场景作通过声明；每个部署环境仍应按 [管理员验收清单](GITLAB_SETUP.md) 检查自己的网络与服务器规则。
